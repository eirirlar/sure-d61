# SUREWAVE D7.4 cost model — v2 → v3 changelog

Version 3 of the D7.4 techno-economic cost workbook, rebuilt in Excel from the v2 Google Sheets export. Inputs are unchanged except for four new end-of-life inputs. All calculation sheets are rebuilt.

## Files

- `surewave/deliverables/2026-11-20_surewave_d7.4_costs_v3.xlsx` — the workbook (deliverable). Every formula's result is stored next to the formula, so Excel shows numbers even in Protected View; Excel recalculates when editing is enabled.
- `scripts/build_d74_workbook.py` — builds v3 from the v2 workbook in about 2 minutes. It assembles the formulas with openpyxl, evaluates them with the `formulas` library and writes the file with xlsxwriter. No desktop applications needed. Re-run after any change to the v2 inputs.
- `scripts/d74_cost_model.py` — Python reference model (test oracle): `v2_outputs` reproduces v2 exactly, `v3_outputs` is the corrected model with each correction as a switch. It also produces the year-by-year cash flows, so every workbook cell has an independent expected value.
- `scripts/test_d74_cost_model.py` — 19 tests, about 5 minutes (see *Verification*).
- `scripts/d74_changelog.py` — prints the result tables below.

Python packages: openpyxl, xlsxwriter, formulas (pulls in numpy), pytest.

## Workbook structure (v3)

| Sheet | Content |
|---|---|
| README | Version, how to use, conventions, system boundary, changes from v2 |
| summary | CAPEX, OPEX, reinstallation, end of life, revenue, LCOE, NPV, ROI, payback, IRR for the 27 main cases |
| in_gen | General inputs (unchanged), plus a new *End of life* section (rows 53–57) |
| in_loc | Inputs per site and size (unchanged) |
| inter_gen | Derived general inputs (unchanged) |
| out_loc | One column per case: 27 main cases (9 sites/sizes × base/pes/opt) and 45 sensitivity cases. Rows 2–10 define the case (location, variant, discount rate, cable alternative, pontoon design) |
| cf | Year-by-year cash flows per case, years 0–55: operating flag, module age, production, O&M, CAPEX, reinstallation, end of life, revenue, net cash flow, discount factor, cumulative discounted net, payback flag; NPV on a rate grid for the IRR |
| pontoons | Pontoon weights and material prices (inputs, unchanged); cost per design and pontoon type (SUMIFS); cheapest per type (MIN); totals per installation size and case |
| freight, harbors, aggregates | Unchanged |
| sens_discounts, sens_subsea_cable, sens_pontoons | Same layout as v2, now formulas pointing at the sensitivity case columns in out_loc |

Formulas use only functions available in desktop Excel: no `LAMBDA`, `MAP`, `SCAN`, `FILTER`, `SEQUENCE`, `UNIQUE`, `MINIFS`. The Google Sheets name `V` (an unused `LAMBDA` helper) is removed. Every number fits its column.

## Corrections

| # | v2 behaviour | v3 |
|---|---|---|
| 1 | Inputs `maintenance_pontoons_*` (€103k/yr for m_10), `inverters_transformers_cost` (€240k) and the nine SCADA items (€39k) were defined but not used by any formula, while the D7.4 annex says CAPEX includes inverters and OPEX includes pontoon O&M | All three included. `inverters_transformers_cost` is CAPEX in year 0 and covers the inverter replacements over the life, as D7.4 §4.3.1 says; there is no separate replacement cash flow |
| 2 | LCOE counted second-life production and O&M but not the reinstallation capital cost (NPV did include it) | LCOE = all discounted lifetime costs / discounted lifetime production |
| 3 | Discount factor `(1 − r)^t`, operation from year 0, extra `(1 − r)` factor on second-life terms | `1/(1 + r)^t`, CAPEX in year 0, operation in years 1–50, reinstallation in year 25, end of life in year 50 |
| 4 | IRR on cash flows already multiplied by `(1 − r)^t`, years 0–24 only | IRR on undiscounted net cash flows, years 0–50. Late outflows can give more than one root; the model reports the highest rate between −10 % and 50 % at which NPV = 0 |
| 5 | `replacement_of_pv_system_*` not multiplied by `rings_count` (installation inputs were) | Multiplied by `rings_count`. Affects only the 5 × 2 MW cases |
| 6 | No end-of-life costs | New inputs in in_gen: `decommissioning_pontoons_cost_factor` = 1.0 and `decommissioning_pv_system_cost_factor` = 1.0 (removal costs the same as installation, as D7.4 §4.4 assumes), `pv_module_disposal_cost_per_kw` = 0 (labour and material value assumed to cancel), `residual_value_fraction` = 0 (no scrap value for the structure) |
| 7 | Freight rate looked up with `total_pvc_cost` (€69,987) instead of the container count (36), so every case got the cheapest band (€0.706/km) | Looked up by container count (€1.037/km for 36 containers). m_10 freight €73.7k → €108.3k |
| 8 | Pontoon totals (`pontoons!AA4`, `AA5`) were Google Sheets formulas that Excel cannot evaluate, frozen at their last value; the formula also added the pontoon counts (91 for 10 MW) to the euro total | Recalculate from the pontoon inputs; counts no longer added (−€91) |
| 9 | Pessimistic columns used the optimistic `inter_gen` column for panel and cable costs; the optimistic second-life production used the base discount rate and lifetime; several rows used the base cooling and hinge values | Each variant uses its own inputs throughout. No Dir values were changed |
| 10 | Sensitivity sheets were pasted values from an earlier run (m_10 "no subsea cable": CAPEX 9.49M, LCOE 0.0625, IRR 10.69 %, against live 9.44M, 0.0622, 10.83 %) | Calculated live from 45 sensitivity case columns |
| 11 | Dir for the electricity sale price (`solar_energy_target_price`) was +1, so the pessimistic case sold electricity at €0.1248/kWh and the optimistic case at €0.1152/kWh | Dir −1: pessimistic €0.1152/kWh, optimistic €0.1248/kWh. A test now checks every Dir input by input: applying only its pessimistic value must lower NPV and only its optimistic value must raise it. On the v2 inputs this flags the price and nothing else |

Unchanged on purpose:
- The base case uses the cheapest design per pontoon type, as in v2 and as D7.4 Appendix A.3.6 states. For all three site sizes this is O0 Conv Ref (conventional concrete shell, polystyrene core; D7.3's "Conventional design") for every pontoon type. D7.4 §3.2.1 lists four designs whose figures correspond to O1–O4 and labels O1's figures "Conventional"; O0 is not named in the text. The D7.4 revision needs to correct the table and say which design the base case uses.
- Substation outside the system boundary. The base case connects through a 300 m floating MV cable to an existing or shared offshore substation, as D7.4 §3.2.2 assumes and D7.5, D7.6, D8.3, D8.4 and the final technical report all describe. The export cable to shore stays a sensitivity, priced as cable cost per metre × distance to shore, without losses, cable landing or onshore substation.
- Payback is discounted, as in v2: the first year in which the cumulative discounted net cash flow is ≥ 0, now over the full life.
- New modules at reinstallation are bought at today's price (no price decline assumed).
- `container_transport_cost_road` / `_sea` (in_gen) and `anchors_count`, `pontoons_count`, `solar_pipe_distance`, `pipe_wavebreaker_distance` (in_loc) stay unused: freight comes from the freight table, and mooring and pipe costs from the weights. Listed in the test as documented-unused.

## Verification

`python -m pytest -p no:cacheprovider scripts/test_d74_cost_model.py`: 19 passed (2026-11-20), about 5 minutes, no desktop applications.

1. Python v2 replica = every cached v2 output (27 cases × 31 rows, relative tolerance 1e-9). This proves the inputs are read the same way the sheet reads them.
2. Every formula cell of the v3 workbook (62,207) has an expected value computed independently from the inputs by the Python model. A coverage test fails if any formula cell lacks one.
3. Every formula result, evaluated with the `formulas` library, matches its expected value (tolerance 1e-7). This covers the input-variant columns, inter_gen, the pontoon grid, every out_loc row in all 72 case columns, every cf cell, summary and all three sensitivity sheets.
4. The delivered file contains the same formulas and stores exactly these results.
5. Every number fits its column in its number format (no `###`), with a negative control. No error values, no non-portable functions, no defined names.
6. Every in_gen / in_loc input is used by a formula or listed as documented-unused.
7. Input changes move the results, and the Python model agrees with the workbook after the change: doubling the CC concrete price; a 6 % discount rate together with a decommissioning factor of 3. The sensitivity cases keep their own discount rate.
8. Unit tests: IRR hand example (13.066 %), IRR with two roots takes the higher one, freight band lookup, cheapest pontoon per type, the v2 frozen pontoon value (2,118,899) reproduced including the count error, and cash-flow timing (CAPEX year 0, reinstallation year 25, end of life year 50, degradation reset, discount factor 0.13009 at year 25).

9. Input directions: every input with a Dir value moves NPV the way its Dir claims, checked input by input for all nine sites and sizes, with a negative control on the v2 inputs that must flag exactly the electricity price. In the workbook's own results the scenarios are ordered pessimistic < base < optimistic for NPV, and the reverse for LCOE, for every site and size.

Independent check of the `formulas` library: on 2026-11-20 all 62,207 formula results agreed with a LibreOffice recalculation of the same workbook. LibreOffice is no longer part of the pipeline.
